# 0.2.6-extract: native slider geometry + bounded black-flash A/B

Baseline: a62824f797244faddaa5a679e8dd9be250c161ff (0.2.5). No user logs, screenshots or video are committed.

Device evidence (iOS 17.2.1, user's 0.2.5):
- Screenshots: expanded slider outer glass radius was visibly different from the private fill mask.
- `liquidasscc_3.log` lines 1681–1705: expanded outer glass/material radius 75 while stock private fill material radius 42. Lines 1726–1754: collapsed glass/material 38.5 while stock fill material radius 21.
- The video confirms a dark expanded card remains visible after shrinking before the collapsed card becomes light again. It does not prove one renderer cause.
- Log lines 1176–1208 show custom encoding succeeds for a 240x239 to 217x216 near-uniform route. Lines 1232–1772 also show stock geometry fallback in other nonuniform transitions. R13 is first-three-only; ready is atom-deduplicated.

Normal behavior changes:
1. Glass slider radius follows the stock outer MTMaterialView radius. The plugin no longer forces half-width radii onto stock slider/fill materials.
2. Remove the global CALayer cornerRadius setter override and cornerRadius animation value rewriting. Stop writing module/content-container radius during expansion. Keep only static small-toggle fill rounding when no animation keys are present.
3. `filterWithType:` replacement attempts clear `_filterAttached` first; exceptions and invalid CABackdropLayer also clear it, so the stock material is restored rather than hidden behind stale status.
4. Fix restore-defaults: keys written from Root.plist are no longer included in `keysToRemove`. Global and CC enable remain preserved.
5. 0.2.5 late material retry, first-frame glass radius, original icon, style alignment and conservative geometry mapping remain. The 0.85–1 and 1% mapping guard is not widened.

Opt-in diagnostics (default false):
- `Debug.Renderer.StockOnly`: leaves already-executed Apple Gaussian output and skips custom draw. This is an A/B diagnostic, not the normal effect.
- `Debug.TransitionTrace.Enabled`: with Debug Logging on, opens one 25-second trace window after off→on. Renderer logs `[CCTRANS]`; SpringBoard logs `[CCVIEWTRANS]` with the same CLOCK_MONOTONIC milliseconds. Output is state-change / 500ms sampled and capped.
- Normal rendering performs no new transition logging and is not changed to multiply an unproven opacity/alpha contract.

Tests/gates:
- `scripts/test_geometry_native.c` directly tests production native-radius and mapping helpers, including new-log fallback examples.
- `scripts/test_geometry.py` asserts no CALayer corner-radius override or corner animation rewriting, stock slider geometry ownership, stale filter-state reset, default-off diagnostic keys, unchanged visual defaults and icon resources.
- Apple CI must pass dual-arch linking and package audit. Device visuals/animation remain unverified.

Device validation order:
A. Normal defaults: collapsed sliders, brightness/volume long-press and return, music/connectivity long-press and return; compare fills and outlines.
B. If black flash persists, keep Debug Logging on, toggle Transition Trace off→on, reproduce within 25 seconds, send log.
C. Independent A/B: turn Stock Only on and repeat one return. If black flash disappears it localizes to custom output, but does not prove how many times alpha should be applied.
D. Turn both diagnostic switches off after testing.
